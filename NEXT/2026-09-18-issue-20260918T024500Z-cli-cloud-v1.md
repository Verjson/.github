title: Upgrade the protected deployment CLI to cli-cloud v1

Upgrade the immutable container-deployment contract to `@verjson/cli-cloud@1.0.0`,
including its verified lock graph and the exact behavioral contract assertions.

The major bump was exercised against the installed package rather than a transcribed
interface, and the consumer-visible surface is **strictly additive**: extracting every
`commander` command, option, and argument literal from `dist/cli.js` in both versions
removes nothing and adds eight. `bin` (`verjson-cloud` → `dist/cli.js`), `exports`, and
`engines.node` (`>=24.0.0`) are unchanged from 0.29.1 — `engines` in particular is not
part of this upgrade, and `.github/workflows/container-deployment.yml` already pinned a
satisfying `24.19.0` before it. `runner update <lane>` keeps `--cloud`, `--project`,
`--runner-mode`, `--release-manifest`, `--release-variant`, and `--only`, so
`scripts/container_deployment_controller.py` needs no adaptation.

The one added command is `runner-host-evidence`, new in 1.0.0 rather than pre-existing.
It carries a `--read-only-ssh-private-key <path>` **required** option, so the new surface
takes a credential-bearing input. Nothing in this repository calls it:
`scripts/container_deployment_transport.py:419` still rejects `host-export` before any
credential read, which stays correct as a fail-closed default until the controller can
construct a complete request.

Two hand-transcribed mirrors are corrected in the same commit, since a documented copy of
an exact pin or range cannot be caught by the compiler or the contract tests.
`docs/v1-readiness/README.md` had drifted to `0.28.1` for this pin, and recorded
`@verjson/cli`'s and `@verjson/cli-cloud`'s own dependency ranges as narrower than the
packages actually declare — overstating remaining v1-readiness work by naming blockers
that had already cleared.

Follow-up work to wire the new export API is tracked in #1451. The transitive `@verjson/infra` resolution moves from `0.19.1` to `0.20.1`. That was not
required by the upgrade — cli-cloud 1.0.0 accepts both — but `0.19.1` was the oldest of
the three versions GitHub Packages retains, so one more `@verjson/infra` release would
have deleted it and 404ed `npm ci` in the deployment workflow. Auditing every
GitHub-Packages pin in one pass is cheaper than diagnosing them one 404 at a time.
