---
date: 2026-09-18
issue: 1430
title: Stop pipefail from reporting grep -q's early exit as a contract violation
impact: patch
---

`grep -q` exits on its first match. Reading from a pipe, that closes the pipe while the
producer is still writing, so the producer dies on `SIGPIPE` and `set -o pipefail` reports
`141` as the pipeline's status. Thirty-nine assertions across eighteen scripts were built on
that shape, so any of them could redden a required check on a pull request whose diff could
not have caused it — `ci-eligibility.test.sh` did exactly that on #1417, reporting that
`node-ci.yml` lacks `statuses: read` when it grants it.

Measured on the reported assertion at 6 concurrent workers: 425 spurious failures in 9000
iterations, every one `141`, against 0 in 9000 after the fix; 0 in 200 unloaded, which is
why it survived so long. Each site now drops `-q` and redirects to `/dev/null`: without
`-q`, `grep` must read to EOF, so the producer never sees `EPIPE`. The exit status and the
assertion it feeds are unchanged.

`scripts/ci-gate/pipefail-sigpipe.test.sh` keeps the shape out. It reproduces the failure
deterministically — by writing more than a pipe can hold after the match, so the producer
must block on a consumer that has already left, rather than by sleeping or stressing — checks that the remedy still reports a genuine
non-match as `1`, and scans every tracked script under `scripts/` — asserting the
enumeration is non-trivial so an empty scan cannot pass for a clean one.

Three further occurrences in `scripts/gen-changelog-caller.sh` are left alone deliberately:
they are emitted verbatim into the generated adopter artifact `changelog-contract.test.sh`,
so fixing them here changes generated bytes in every adopter and fails
`required-checks-audit.test.sh` with `generated-contract-byte-drift`. Those, and the same
shape inside generated workflow `run:` blocks, belong to the regeneration at a new contract
SHA tracked in #1431. The frozen conformance regression fixtures are untouched.

The guard deliberately does not pin *which* non-zero status the hazard produces. Where the
producer dies on the signal, `pipefail` reports `141`; where bash handles `EPIPE` inside a
builtin `printf` instead, it reports `1`. Both were observed — `141` locally, `1` on the
hosted runner. `1` is the worse of the two, being indistinguishable from an honest "pattern
not found", and pinning `141` would have made this guard fail on exactly the platform whose
behavior it describes.

Review hardening: the guard matched one spelling of the hazard, one line at a
time, so a planted file carrying four genuinely offending shapes was enumerated
and reported clean. The worst miss is trailing-pipe continuation — `producer |`
on one line with `grep -q` on the next — which is this repository's dominant
style at 62 lines across 13 scripts, so the guard would have missed real
regressions in precisely the shape most likely to produce them.

Continuations are now joined before matching, and the pattern covers any
early-exiting grep on the read end of a pipe: separated flags (`grep -E -q`),
the long option (`grep --quiet`), `egrep`/`fgrep`, and command or environment
prefixes such as `LC_ALL=C grep -q`, `command grep -q`, and `timeout 5 grep -q`.
The pathspec widened from `scripts/` to every tracked `*.sh`, which brings the
composite-action shell under `.github/actions/` into scope.

Each shape is asserted individually through the same `scan_file` path the tree
scan uses rather than against the raw pattern — the continuation case is
invisible without the joiner, so testing the pattern alone would have proved
nothing — and the safe forms (a file argument, a here-string, and the redirect
this fix applied 39 times) are asserted not to trip it.
