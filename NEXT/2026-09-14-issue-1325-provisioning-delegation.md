title: Define owner-approved delegation for agent-operated provisioning
---

An owner can now delegate a reviewed provisioning plan to a named executor through a grant document. `config/provisioning-delegation-contract.json` defines the issuer/executor boundary, the effect vocabulary and the owner-gated subset it derives (`ownerConsentRequired: "all"`, so a new effect cannot be added to the vocabulary and silently escape its gate), the immutable `Verjson/verjson-ci` contract pin, evidence, expiry and revocation requirements; `scripts/provisioning-delegation-validate.py` turns a grant into an authorization receipt offline, with no network call and no credential read. One reviewed grant authorizes every action it lists without per-call reconfirmation. A contract or inventory that cannot be read as a policy document exits 2, which is distinct from the exit 1 that reports a withheld authorization; every declared effect list is rejected unless it is a list of names, because `in` and `set()` both accept a bare string and degrade to substring and character tests that answer permissively rather than raising. Model output, unattended mode, an executor-authored approval field and any unrecognized field are rejected, and every owner-gated effect needs its own consent record with a GitHub-hosted reference and approvers excluding the executor.

`config/app-role-custody-inventory.json` extends the custody record from the three environment-bound roles to all seven owned roles, each with storage, trust, rotation and role-specific positive, negative and insufficient proof. Each role additionally records `migrationStatus`, which keeps the custody an owner decided apart from the custody actually achieved: `merge` and `ai-review` are decided environment-only but still have surviving organization secret copies, each named with the visibility `config/org-actions-secret-policy.json` declares for it and the issue tracking its withdrawal. The validator refuses an inventory in which a role claims its decided custody as achieved while its own record says broad copies are pending, so the record cannot overstate containment. Both custody values must be stated before they are compared — two absent values compare equal — each surviving copy must be named as an object, the tracking reference must be hosted, and the inventory must cover exactly the roles `cohort.requiredRoles` names in the contract. The three environment-bound roles are keyed by the same tokens `.github/workflows/app-key-environment.yml` accepts, so the `ai-review` role resolves to the `ai-review-app` environment with no translation table. A target may request only its role's permitted effects and must declare exactly the catalog permission ceiling, which is how ai-review/merge/release separation, read-only ruleset audit, isolated runner control and the supersession enablement gate are enforced mechanically. The contract ships as `defined-not-activated`: merging it authorizes nothing until an owner changes that status in a reviewed pull request. ADR 0177 records the decision; `docs/provisioning-delegation.md` is the runbook.
